# What Symfony 8.2 saves

This app runs on Symfony 8.2. The [`symfony-8.1`](https://github.com/nicolas-grekas/symfony-showcase/tree/symfony-8.1)
branch is the same app ported back to Symfony 8.1: same features, same tests, and every 8.2
feature replaced by what one would write on 8.1, in a commit of its own. The
[`symfony-7.4`](https://github.com/nicolas-grekas/symfony-showcase/tree/symfony-7.4) branch
does the same from 8.1 to 7.4, the long-term support version. Each version passes the test
suite against its own version of Symfony.

| | 8.2 | 8.1 | 7.4 | 7.4 to 8.2 |
|---|---|---|---|---|
| PHP files in `src/` | 75 | 111 | 113 | -34% |
| Lines in `src/` | 3,051 | 4,958 | 4,990 | -39% |
| Lines of YAML configuration written for the app | 137 | 143 | 142 | -4% |
| Lines of tests | 1,454 | 1,786 | 1,802 | -19% |

The counts leave out `src/Showcase`, the profiler panel that lists the 8.2 features of each
request, and its test. The configuration lines are the ones the app adds or changes in the YAML
files of `config/`, compared with what the Flex recipes of each version install; comments and
blank lines are not counted. The three versions need about the same configuration: 8.2 adds
some for its new features, and moves some into attributes, like the workflow and the encrypted
column. The recipes of 8.2 also install less: dev and prod values follow the debug mode and test
values follow `framework.test` (symfony/symfony#66876, #66877, #66880, #66882, #66887), so the
YAML of the app went from 379 to 318 lines while the 8.2 recipes were trimmed
(symfony/recipes#1597, #1598).

On 8.1, the app needs 1,907 more lines of code, and 332 more lines of tests: 261 for test
helpers that 8.2 ships, the rest for the `Cache-Status` header that 8.1 makes the app write and
for what the 8.2 testing tools do in one call.

On 7.4, the app needs 32 more lines of code than on 8.1, and 16 more lines of tests. Symfony 8.0
has the features of 7.4 without its deprecated code, so this difference comes from the features
of 8.1 and from a few behaviors that 8.0 changed: see [From 7.4 to 8.1](#from-74-to-81).

On 8.2, the same requests also run 23% fewer CPU instructions than on 8.1, and 20% fewer than
on 7.4: see [Performance](#performance).

The 8.1 versions keep the behavior. Where they differ, the sections below say how. Each
section links to the commits of the `symfony-8.1` branch, where the 8.1 code can be read in full.
On 7.4, the code of these sections is the same as on 8.1, except for the console sub-commands,
`#[Serialize]` and the OpenID Connect login, which also use features of 8.0 and 8.1.

## Login with OpenID Connect

On 8.2, the `oidc_login` authenticator runs the authorization code flow, provisions the users
from the claims, refreshes the access token, and handles the logout on both sides:

```yaml
# config/packages/security.yaml
oidc_login:
    provider_uri: '%env(OIDC_ISSUER)%'
    client_id: '%env(OIDC_CLIENT_ID)%'
    client_authentication:
        client_secret_basic: '%env(OIDC_CLIENT_SECRET)%'
    scope: [profile, email]
    user_identifier_claim: email
    refresh_access_token: true
    enable_end_session: true
    backchannel_logout: true
```

On 8.1, the app writes it: an authenticator (state, nonce and PKCE, code exchange, ID token
checks), a client for the discovery, JWKS, token, UserInfo and end-session endpoints, a session
listener that refreshes the token and ends the sessions the provider logged out, and a store of
those sessions: 484 lines in `src/Security/Oidc*.php`. The same tests, with a fake provider,
cover both versions. On 8.1 the app keeps one pending login per session, and does not fetch the keys again when a
token is signed with an unknown one. ([8f635e0](https://github.com/nicolas-grekas/symfony-showcase/commit/8f635e0))

## Columns encrypted at rest

On 8.2, KeyManagement encrypts a column with envelope encryption: a data key wrapped by a key
management service, created once and stored in a table. The `#[Encrypted]` attribute marks the
column:

```php
#[ORM\Column(nullable: true)]
#[Encrypted(key: 'speaker.contact')]
public ?string $phone = null;
```

```yaml
# config/packages/key_management.yaml
key_management:
    clients:
        default: '%env(KMS_DSN)%'
    store:
        key_id: speakers
```

On 8.1, the app writes a Doctrine type and a store of data keys wrapped by a master key read
from the environment, with the sodium extension, and registers the type in `Kernel::boot()`:
224 lines in `src/Encryption`. What 8.1 cannot get without a third-party SDK: the master key in
a cloud KMS chosen by its DSN (AWS, Azure, GCP, Vault, KMIP), and the commands to rotate it.
([6367255](https://github.com/nicolas-grekas/symfony-showcase/commit/6367255))

## Messenger flows

On 8.2:

```yaml
# config/packages/messenger.yaml
messenger:
    identity_stamps: true       # correlation, message and causation ids on every message
    transports:
        events:
            dsn: '%env(RABBITMQ_DSN)%/%%2f/events'
            # stored in the database transaction, sent to RabbitMQ after it
            outbox: 'doctrine://default?queue_name=outbox'
    buses:
        messenger.bus.default:
            middleware: [logging, doctrine_dbal_transaction]
```

```php
// the travel details are sent once the booking succeeds, and the organizers are alerted if it fails for good
$this->bus->dispatch(ChainStamp::envelope(new BookSpeakerTravel($proposal->id), new SendTravelDetails($proposal->id))
    ->with(new DispatchOnFailureStamp(new AlertOrganizers(...))));

#[AsMessageHandler(after: NotifyReviewersOfNewProposal::class)]
```

On 8.1, each of these is code of the app: a handler that forwards the events from the outbox
(and every handler of these events must say which transport it consumes), a middleware and a
stamp for the correlation id, a listener of failed messages that dispatches the alert, the
booking handler dispatching the next message itself, a logging middleware, a mailer listener for
the rate limit of the mail provider, priorities instead of `after`, and the failure transport
read directly instead of `FailedMessageRepository`.
([10 commits, from 3762427 to a946384](https://github.com/nicolas-grekas/symfony-showcase/compare/3762427~1...a946384))

## Forms from data classes

On 8.2, a data class is its own form type, and the field types are guessed from the PHP types:

```php
#[AsFormType]
final class SpeakerData
{
    #[FormField]
    #[Assert\NotBlank]
    public ?string $name = null;

    #[FormField(TelType::class, ['required' => false, 'help' => 'Only given to the travel agency if your talk is accepted.'])]
    public ?string $phone = null;
}
```

8.2 also brings `PolymorphicCollectionType` (the slides and videos of a proposal),
`BoundsType` (the date ranges of a conference), the `entry_name` and `choice_help` options,
step groups in form flows, and `Valid(restrictGroups: false)`.

On 8.1: 8 more form type classes in `src/Form`, a collection type with one prototype per kind of
material, a period type with a constraint ordering its bounds, a form theme block for the help
of each choice, and a `Callback` per step to validate the data of the step.
([8 commits, from 655e14a to f5b986f](https://github.com/nicolas-grekas/symfony-showcase/compare/655e14a~1...f5b986f))

## API access tokens

On 8.2:

```php
#[IsGranted('OAUTH2_SCOPE(proposals:write)')]
```

```yaml
access_token:
    token_handler:
        oidc:
            discovery:
                base_uri: '%env(OIDC_ISSUER)%/'
                check_issuer: true
    resource_metadata:
        authorization_servers: ['%env(OIDC_ISSUER)%']
        scopes_supported: ['proposals:write']
```

A token without the scope gets the RFC 6750 `insufficient_scope` challenge, clients find the
authorization server in the RFC 9728 metadata document and in the `WWW-Authenticate` header, and
the keys of the discovery document only verify the tokens of the issuer it announces.

On 8.1: a listener copying the scopes onto the security token, a voter, an entry point and
access denied handler building the challenges, a controller serving the metadata document, and a
listener checking the issuer announced by the discovery document.
([5 commits, from 6a87250 to 73cd99d](https://github.com/nicolas-grekas/symfony-showcase/compare/6a87250~1...73cd99d))

## Standard Webhooks

On 8.2, one line makes the webhooks the app receives and the ones it sends follow
[Standard Webhooks](https://www.standardwebhooks.com/):

```yaml
webhook:
    signature_format: standard
```

On 8.1: a request parser checking the signatures and the timestamp, a signer and a headers
configurator for the sending side, and the signature helper they share.
([3 commits, from 119befa to b2a6c5d](https://github.com/nicolas-grekas/symfony-showcase/compare/119befa~1...b2a6c5d))

## Asking for the password again

On 8.2, reviewers confirm their password before deciding on a proposal:

```yaml
security:
    recent_authentication_lifetime: 900
```

```php
if (!$this->accessDecisionManager->decide($token, ['IS_AUTHENTICATED_RECENTLY'])) {
    // the firewall asks for the password again instead of denying access
    $vote?->requestReAuthentication(self::DECIDE);

    return false;
}
```

On 8.1, a class records the time of each interactive login on the token, tells the voter how
old it is, and, as the access denied handler of the firewall, sends the user back to a login
form that only asks for the password. ([07ccd19](https://github.com/nicolas-grekas/symfony-showcase/commit/07ccd19))

## `Cache-Status` header

On 8.2, the HTTP cache of the kernel tells what it did in an RFC 9211 `Cache-Status` header:

```yaml
when@prod:
    framework:
        http_cache:
            enabled: true
            cache_status: Symfony
```

On 8.1, a decorator of the `http_cache` service turns the traces of `HttpCache` into the
header, with its own tests. It cannot tell the status of the backend when a stale response is
served on error. ([1c96829](https://github.com/nicolas-grekas/symfony-showcase/commit/1c96829))

## Locked and rate-limited actions, signed links

On 8.2:

```php
#[RateLimit('ticket_purchase', key: new Expression('args["user"].getUserIdentifier()'), methods: 'POST', exposeHeaders: true)]
#[Lock('ticket-sale-{conference}', blocking: true, ttl: 10, methods: 'POST')]
public function buy(...): Response
```

```twig
{{ url('ticket_show', {id: ticket.id})|sign_url(ticket.conference.endsOn|date_modify('+1 day')) }}
```

On 8.1, the action consumes the limiter, sets the `X-RateLimit-*` headers and takes the lock
itself, and a service signs the links that the controllers pass to the templates. The limiter
cannot tell when the window resets while tokens remain, so the 8.1 version sends no
`X-RateLimit-Reset`. Taking advisory locks on the connection of Doctrine
(`lock: {service_id: ..., advisory: true}` on 8.2) means redefining a service of the lock factory.
([4 commits, from a6e6c7b to c50d077](https://github.com/nicolas-grekas/symfony-showcase/compare/a6e6c7b~1...c50d077))

On 8.2:

```php

$client->followRedirect();
```

([4 commits, from 961389e to e827e85](https://github.com/nicolas-grekas/symfony-showcase/compare/961389e~1...e827e85))

## Everything else

These 8.2 features make the code shorter or clearer, without changing its size much:

- The configuration of each component at its own root key: `messenger:` instead of
  `framework: messenger:`, with a JSON schema that editors use to validate and complete the
  YAML files. 8.1 has no schema.
- A workflow declared in its class, with enum places and its listeners next to it
  (`#[AsWorkflow]`, `#[Transition]`). On 8.1 the workflow is configured in YAML and its
  listeners name it.
- Console sub-commands: `bin/console conference list`, and the accepted values of enum options
  listed in the help. On 8.1, `conference:list`.
- The email channel of the Notifier sends from the global `From` header of the mailer. On 8.1
  the app sets an envelope sender too.
- `#[MapEntity]` with closures and lists, `DatePoint` properties mapped without a `type`, and
  `UuidV7::createBoundaries()` to query a time range by id.

## From 7.4 to 8.1

| What 8.0 and 8.1 provide | 8.1 | 7.4 |
|---|---|---|
| Commands declared on methods (8.1) | 1 class | 3 classes, +32 lines |
| Lists of enum cases in console options (8.1) | `TicketStatus ...$status` | an array option, +6 lines |
| `InputFile` (8.1) | `InputFile::fromPath()` | `Filesystem::readFile()`, +1 line |
| `#[Serialize]` (8.1) | the actions return the resources | the actions call `json()`, 5 lines fewer |
| Empty user identifiers refused (8.0) | built in | 1 more check, +16 lines of tests |
| `eraseCredentials()` removed from `UserInterface` (8.0) | nothing to write | 1 empty method, +6 lines |
| Serializer data in the profiler (8.1) | built in | 2 lines of config |
| Allowed values of `APP_ENV` (8.1) | `getAllowedEnvs()` in the kernel | no check, 8 lines fewer |

On 8.1, the conference commands are methods of one class, whose `#[AsCommand('conference')]`
prefixes their names. On 7.4, each command is a class with an `__invoke()` method. The tickets
command takes a list of statuses: 8.1 turns them into enum cases, while 7.4 takes strings that
the command converts, with the same error message for an unknown status. The import command
reads its files with `Filesystem::readFile()`, so a missing file is reported by the error of
`file_get_contents()`. The usages that `#[AsCommand]` declares were not shown on 7.4 for such
classes: [symfony/symfony#66863](https://github.com/symfony/symfony/pull/66863) fixes it.
([e6d6e4b](https://github.com/nicolas-grekas/symfony-showcase/commit/e6d6e4b), [f2fcda6](https://github.com/nicolas-grekas/symfony-showcase/commit/f2fcda6), [b8ffa46](https://github.com/nicolas-grekas/symfony-showcase/commit/b8ffa46))

On 7.4, the API actions return `$this->json($resources, context: ['groups' => ['list']])`. The
JSON is the same, except that `json()` escapes `<`, `>`, `&`, `'` and `"` inside strings.
([b4070fe](https://github.com/nicolas-grekas/symfony-showcase/commit/b4070fe))

Since 8.0, `UserBadge` refuses an empty user identifier. 7.4 only triggers a deprecation, so the
OpenID Connect authenticator checks that the `email` claim is not empty, and a test covers it.
On 7.4, `UserInterface` still declares `eraseCredentials()`: `User` implements it as an empty
method marked `#[\Deprecated]`. ([5d614f4](https://github.com/nicolas-grekas/symfony-showcase/commit/5d614f4), [f48da7b](https://github.com/nicolas-grekas/symfony-showcase/commit/f48da7b))

On 7.4, the profiler collects the data of the serializer only with
`framework.profiler.collect_serializer_data: true`, and triggers a deprecation without it. The
8.1 recipe adds `getAllowedEnvs()` to the kernel, and the kernel then refuses any other value of
`APP_ENV`; 7.4 has no such check. The 8.1 recipe also adds `AGENTS.md` and `CLAUDE.md`, the
instructions for coding agents. ([86cf76e](https://github.com/nicolas-grekas/symfony-showcase/commit/86cf76e), [6f3bb48](https://github.com/nicolas-grekas/symfony-showcase/commit/6f3bb48), [4a4a442](https://github.com/nicolas-grekas/symfony-showcase/commit/4a4a442))

One behavior differs: the Doctrine and AMQP transports of 7.4 delete a message they cannot
decode, where 8.1 retries it and then sends it to the failure transport. No configuration of
7.4 does the same, so on 7.4 such a message never shows in the failed messages of the back
office.

## Performance

The three versions were installed from fresh clones (Symfony 8.2.x-dev, 8.1.8 and 7.4.20) and
replayed the same twelve requests in the `prod` environment, with PHP 8.5.10 and OPcache, JIT off.
Each request boots a new kernel from the cache, like PHP-FPM does, then the response is sent and
the kernel terminated. The HTTP cache of the kernel is bypassed, so each request does the whole
work, and the connections to PostgreSQL are persistent, so that authenticating to the database
does not hide the rest. The pages of the back office and the call for papers are requested as a
logged-in administrator.

The 8.2 numbers include the DeepClone polyfill of symfony/polyfill 1.x (symfony/polyfill#716) and
four pull requests that were still open when measured: symfony/symfony#66909, #66910, #66911 and
#66912 (see below).

Wall-clock times vary too much on a laptop, so the table counts the instructions of each request
with callgrind, in millions, each from two runs that differ only by ten requests. The GC is off:
a PHP-FPM request rarely fills the root buffer of the GC, while the replay loop does it every 16
requests or so, which put a cycle collection in the count of some requests and not of others. The
boot alone is counted on twenty kernels kept until the end, so that neither `shutdown()` nor
freeing the previous kernel is counted.

|---|---|---|---|---|---|
| home page | 5.02 | 4.97 | 7.20 | 7.12 | 5.08 |
| conference page | 7.00 | 6.84 | 9.19 | 8.88 | 6.90 |
| schedule page | 5.31 | 5.21 | 7.50 | 7.33 | 5.36 |
| login page | 4.07 | 4.07 | 6.37 | 6.35 | 4.28 |
| API: list of conferences | 3.75 | 3.66 | 6.12 | 5.54 | 3.84 |
| API: a conference and its talks | 6.14 | 5.87 | 9.28 | 8.44 | 6.09 |
| API: streamed talks | 4.79 | 4.59 | 6.36 | 5.98 | 4.71 |
| API: catalog | 1.69 | 1.69 | 2.29 | 2.28 | 1.89 |
| call for papers form | 13.32 | 13.22 | 15.17 | 14.91 | 13.28 |
| back office dashboard | 6.01 | 5.97 | 8.22 | 8.05 | 6.00 |
| conference editor | 17.60 | 17.44 | 19.26 | 18.94 | 17.36 |
| schedule editor | 8.49 | 8.36 | 10.59 | 10.32 | 8.41 |

On 8.2, the twelve requests run 23% fewer instructions than on 8.1 and 20% fewer than on 7.4; the
public pages run about 30% fewer. Booting the kernel alone runs 57% fewer instructions than on
8.1: among other changes, the container builds a `CompiledEventDispatcher` that gets its listeners
in one array, and the KeyManagement bundle no longer creates the DBAL connection while booting.
The 8.1 version of the app running on Symfony 8.2 does as well as the 8.2 version, so the gain
comes from the framework, and the 8.2 features cost about the same as the code they replace. On
the streamed talks, `#[Serialize(map: ..., stream: true)]` and `#[Cache(target: 'CDN')]` cost 2%
more than the 8.1 code, which maps the talks, calls the stream writer and sets the header by hand.

Since Symfony 8.1, the caches dumped by VarExporter (Doctrine, serializer and ObjectMapper
metadata, the DQL query cache) are rebuilt on each request by `deepclone_from_array()`. With the
`deepclone` extension (`pie install symfony/deepclone`) instead of its PHP polyfill, the twelve
requests run 1.5% fewer instructions, and the API requests up to 4% fewer.

Measuring found work that 8.2 did not need to do:

- symfony/symfony#66907: the ObjectMapper skips the PropertyAccessor for plain public properties
  (-24% on the conference API);
- #66904: `PropertyAccessor::isReadable()` uses its path cache;
- #66906: the `#[Serialize]` listener builds its services on demand;
- symfony/polyfill#716: `deepclone_from_array()` needs 27% fewer instructions;
- #66909: booting the kernel no longer creates the KeyManagement encrypter of the DBAL types, its
  key store and the DBAL connection;
- #66910: `Type::list()` no longer builds a default key type it throws away;
- #66911: the return types that `#[Serialize(stream: true)]` reads from docblocks are cached and
  warmed up (-20% on a streamed controller without `map:`);
- #66912: the guesses of the TypeInfo form type guesser are cached and warmed up (-1.2% and -1.6%
  on the two form pages that guess field types).
